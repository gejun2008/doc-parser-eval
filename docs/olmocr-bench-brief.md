# Infinity-Parser2 与 Azure DI：公开基准对照（概要）

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-30 |
| 被测 | Infinity-Parser2 API（端点回显 `inf-mllm`；厂商称 Flash 2.1），2026-09-18 运行 |
| 对照 | Azure Document Intelligence `prebuilt-layout`，API `2024-11-30`，公司 UAT 网关，2026-09-29 运行 |
| 定位 | 公开基准上的**准入检查**。能否替代，以自建金融文档集的结果为准（见 `evaluation-report.md`） |

**一句话**：同一批页面、同一套判分代码下，两家总体未观察到显著差异。**表格是 Azure 明显更好**，
Infinity 的优势出现在手写老信件上，与我们的业务场景关系不大。

---

## 1. 测试集：用什么测

**olmOCR-Bench**：AllenAI 公开发布的 PDF 解析基准（ODC-BY 许可），共 1,403 页、7,019 条测试。
选它的理由：

- **第三方出题**：测试题和判分代码都不是我们写的，也不是厂商写的
- **判分代码原样使用**：官方代码固定在 commit `ab294c6a`，一行未改
- **可复现**：抽样用固定随机种子；每页的原始输出全部保存，任何数字都能重算

我们按金融文档的相关性抽了 **120 页 / 499 条测试**（不含公式类，见 §3）：

| 子集 | 页数 | 测试数 | 考什么 | 与金融文档的关系 |
|---|---|---|---|---|
| 表格 | 40 | 187 | 单元格的值与行列关系 | **最高**：财报、附注的核心 |
| 小字密排 | 15 | 120 | 小字号长文本不漏字 | 高：接近附注页 |
| 多栏 | 20 | 68 | 阅读顺序 | 中 |
| 老扫描件 | 15 | 75 | 历史信件识别 | 低：15 页中 10 页是手写 |
| 页眉页脚 | 20 | 49 | 页眉页脚不应混入正文 | 中，但两家输出方式不同（§3） |

## 2. 评估方法：怎么判

1. **每条测试只判对或错**。例如「这句话必须出现」「A 段必须在 B 段之前」「这个单元格的右边必须是那个值」。
2. **两家做同一批页、同一批测试**，一条一条配对比较。
3. **只看两家结论不一致的那部分**：「只有 Infinity 对」有几条、「只有 Azure 对」有几条，
   再用 McNemar 检验判断差异是否显著（p < 0.05）。两家都对或都错的条目不影响结论。
4. **不合成总分**：按子集分别给结果。p ≥ 0.05 写「未观察到显著差异」，不写「持平」。

## 3. 公平性：已知的偏差都摆出来

| 事项 | 处理 |
|---|---|
| **厂商主场**：厂商自己在这个基准上报过分（全量 87.6%），不能排除训练时见过这批数据 | 如实写明，对 Infinity 有利；我们跑的是抽样子集，分数不与 87.6% 比较 |
| **输入不同**：Azure 收到 PDF 原件，Infinity 收到 300 DPI 图片（这是厂商 SDK 的做法） | 两家都按各自产品的标准用法调用 |
| **页眉页脚**：Azure 把页眉页脚写成 HTML 注释，判分代码仍当作「出现在正文」，判 Azure 错 | 这一行**不作比较** |
| **公式类**：公司网络装不上渲染公式所需的组件，Azure 侧没法判分 | 两边都去掉公式类，604 条剩 499 条 |
| **调用失败**：Infinity 有 1 页陷入复读、输出被截断；Azure 120 页全部成功 | 两种算法都算了：失败页算错，或两边都去掉这一页。结论相同 |

## 4. 结果

| 子集 | 测试数 | Infinity | Azure | 只 Inf 对 : 只 Az 对 | 结论 |
|---|---|---|---|---|---|
| **表格** | 187 | 64.2% | **86.6%** | 11 : 53 | **Azure 显著更好** |
| 小字密排 | 120 | 87.5% | 82.5% | 11 : 5 | 未观察到显著差异 |
| 多栏 | 68 | 82.3% | 75.0% | 8 : 3 | 未观察到显著差异 |
| 老扫描件 | 75 | 50.7% | 28.0% | 19 : 2 | Infinity 更高，**但以手写为主**，人工抽看两家输出，实际差距没有分数显示的那么大 |
| 页眉页脚 | 49 | 30.6% | 14.3% | 9 : 1 | 不作比较（输出方式不同） |
| *全部，仅供参考* | *499* | *66.9%* | *68.1%* | *58 : 64* | *未观察到显著差异（p = 0.65）* |

**表格为什么差这么多**：Infinity 在 40 页里有 14 页**没有把表格识别成表格**，
整张表被拼成一段普通文字，行列关系丢失，而且不报错。只要识别成了表格，它的单元格正确率是 91%。
这种「表格被拍平」的失败对财报场景风险最高。

## 5. 这一层说明了什么

- **能说明**：在中立的公开题目上，Infinity 的基础解析能力达到 Azure 的水平，可以进入下一步评测；
  表格是需要重点盯的风险。
- **不能说明**：这个基准里没有财报。能否在 HSBC 场景替代，要看自建金融文档集的分文档类型结果。
