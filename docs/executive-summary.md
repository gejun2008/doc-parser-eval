# Infinity-Parser2 替代 Azure DI：评估简报

2026-09-23 · 读者：技术主管 · 完整报告见 [`evaluation-report.md`](evaluation-report.md)，幻灯片版见 `briefing-deck.html`

**测了什么**：53 份公开的 A 股和港股披露文档，按规则选出 210 页，共 1,229 条自动可判的断言。
Infinity 与 Azure DI 跑的是同一批页，只比较双方都成功的 191 页（Azure 有 19 页因公司网关超时失败）。

## 一句话

港股披露文件和 A 股公告可以进入 POC。
但 A 股年报、中报中「页首是上一页续表」的页，Infinity 会**静默丢掉整段表格**，调用照常返回、没有报错；Azure 在同样的页上完整保留。
另外 Infinity **不提供置信度**，没法只把可疑字段挑出来复核。

## 支持的文件格式

| | PDF | 图片 | Office（Word / Excel / PPT） | HTML |
|---|---|---|---|---|
| Azure DI | ✅ | ✅ JPG · PNG · BMP · TIFF · HEIF | ✅ | ✅ |
| Infinity-Parser2 | ✅ | ✅ PNG · JPG · BMP · TIFF · WEBP | ❌ | ❌ |

Infinity 的 Office 文档要先转成 PDF 或图片才能处理，转换后原生的文字和结构会丢失。
出处：厂商 SDK `infinity_parser2==0.4.0`，`utils/file.py` 中的支持格式白名单。

## 哪些 PDF 文档能处理，哪些不能

| 文档类型 | 判断 | 依据 |
|---|---|---|
| 港股年报、中报、招股书 | ✅ **可替代候选，进 POC** | 金额和科目归属两边都没有失败；正文完整性未观察到显著差异 |
| A 股临时公告 | ✅ **可替代候选，进 POC** | 金额两边都没有失败；正文完整性 Infinity 通过更多（这个差距还没排除标点差异的影响） |
| A 股年报、中报（报表附注页） | ⛔ **现阶段不可替代** | 3 页确定性丢表，共 27 个金额，都发生在页首续表上 |
| 需要按置信度分流复核的流程 | ⛔ **不可替代（结构性）** | API 不给置信度，请求里的 `logprobs` 被静默忽略 |
| 港股 KYC 类文件 | ⚠️ 证据不足 | 只有 39 条正文完整性断言，没有金额断言 |
| 扫描件、倾斜件 | ⚠️ 没和 Azure 对照 | 只测了 Infinity：页面倾斜 2° 就无限复读，输出作废 |
| 贸易金融单证 | — 未覆盖 | 找不到合规的公开样本，现有结论不能外推 |

## PDF 处理效果：配对数据对比

| 指标 | n | Infinity | Azure DI | 怎么读 |
|---|---|---|---|---|
| 金额：数值原样出现，次数正确 | 486 | 97.5% | **100%** | 差异显著（p = 0.0005）。Infinity 的 12 条失败中，8 条是真实遗漏，4 条只是减号字形不同 |
| 金额与科目同行（人工确认） | 76 | 100% | 98.7% | 未观察到显著差异 |
| 正文完整性：每页抽 3 行，看是否原样输出 | 448 | **91.3%** | 72.5% | 差异显著，但比对时没统一全角/半角标点，**不能读成「Azure 丢内容」**，正在复判 |
| 全量金额扫描：Infinity 丢表的页 | 73 页 | 3 页，27 个金额 | 配对的 2 页上为 0 | Azure 侧的全量扫描还没跑 |

| 服务与成本（口径不同，只作参考） | Infinity（测试端点） | Azure DI（公司网关） |
|---|---|---|
| 成功率 | 210/210 | 191/210 |
| 单页延迟中位数 | 22.5 s（并发 2） | 17 s（并发 4，含轮询） |
| 吞吐 | 1.6–5.6 页/分，加并发没用 | — |
| 价格 | 厂商还没报价 | 牌价 $10 / 千页 |

每页约 9.6k token。如果按 token 计费，只算输入时单价要低于 **≈ $1.13 / 百万 token**，才能和 Azure 牌价持平。

## 模型基本对比

| | Infinity-Parser2 | Azure DI（prebuilt-layout） |
|---|---|---|
| 技术路线 | 视觉语言模型（VLM），整页图像直接生成 markdown | OCR 加版面分析流水线 |
| 置信度 | **无** | 每个文本片段都有 |
| 确定性 | 同一页调 3 次，99.0% 逐字相同，金额零变化 | 确定性 |
| 认不出来时 | 可能漏掉或凭空生成，调用照常正常结束 | 给低置信度或留空 |
| 版本 | 只能看到别名 `inf-mllm`，看不到具体型号和版本 | 有 API 版本号 |
| 模型来源 | 开源权重（Apache-2.0）；模型自称基于 Qwen3.5，尚未证实 | 闭源托管服务 |

**差别的本质**：OCR 认不准时会报「不确定」，VLM 认不准时照常交付结果。
Infinity 放弃了置信度、确定性和几何坐标框，换来表格结构上的潜在优势。

## POC 范围与退出标准

**范围**
- 港股年报、中报、招股书，加上 A 股公告；只用电子版 PDF，每类至少 300 页。
- 另选至少 50 页「页首续表」做定向测试。
- 两道强制护栏：金额与 PDF 文本层逐个对账；`finish_reason=length` 一律转人工。
- 开测前，厂商必须答复四件事：型号与版本能否锁定、怎么计费、能否提供置信度、生产环境 SLA。

**退出标准（任一触发即停）**
- 丢失或替换金额的页，显著多于 Azure。
- 不能锁定版本，也不承诺变更前提前通知。
- 按合同价、计入人工复核后，单页成本高于 Azure。
- 生产吞吐满足不了业务峰值，或复读退化率超过阈值。

## 还差什么

以下几项在公司电脑上补跑，不用调 API，约 1 小时：
- Azure 侧的全量金额扫描；
- 正文完整性按宽松口径复判（统一全角/半角、去掉标点）；
- 单位/币种字段恢复进对照。

补完后更新本页。步骤见 `photo-numbers-prompt.md` 第二轮。
