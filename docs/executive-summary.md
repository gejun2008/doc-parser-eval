# Infinity-Parser2 替代 Azure DI：评估简报

2026-09-24（已并入第二轮数据）· 读者：技术主管 · 完整报告见 [`evaluation-report.md`](evaluation-report.md)，幻灯片见 `briefing-deck.pptx` / `briefing-deck.html`

**测了什么**：53 份公开的 A 股、港股披露文档，按规则选出 210 页，共 1,229 条自动可判的断言。
Infinity 和 Azure DI 跑同一批页，只比较双方都成功的 191 页（Azure 有 19 页因公司网关超时失败）。

## 一句话

**解析质量上，Azure 在本轮每一项指标上都持平或更好**；Infinity 没有哪一项显著领先。
Infinity 还有三处结构性短板：
- 只接受 PDF 和图片；
- 不提供置信度；
- 在「页首是上一页续表」的页上会静默丢掉整段表格。

替代的理由只可能来自成本（等厂商报价）或私有化部署需求，不会来自解析质量。

## 支持的文件格式

| | PDF | 图片 | Office（Word / Excel / PPT） | HTML |
|---|---|---|---|---|
| Azure DI | ✅ | ✅ JPG · PNG · BMP · TIFF · HEIF | ✅ | ✅ |
| Infinity-Parser2 | ✅ | ✅ PNG · JPG · BMP · TIFF · WEBP | ❌ | ❌ |

Infinity 处理 Office 文档要先转成 PDF 或图片，原生的文字和结构会丢失。出处：厂商 SDK `infinity_parser2==0.4.0` 的 `utils/file.py`。

## 哪些文档能处理，哪些不能

| 文档类型 | 判断 | 依据 |
|---|---|---|
| Word / Excel / PPT / HTML 原生文件 | ⛔ **不能直接替代** | Infinity 不支持这些格式 |
| 港股年报、中报、招股书 | ✅ **关键字段未见差异，可进 POC** | 金额、科目归属：两边都没有失败 |
| A 股临时公告 | ✅ **关键字段未见差异，可进 POC** | 金额：两边都没有失败 |
| A 股年报、中报（报表附注页） | ⛔ **现阶段不能直接替代** | Infinity 3 页确定性整段丢表（其中一页丢了整张 16 个金额的表），没有任何报错；Azure 在这类页上也缺了几次金额，原因待查 |
| 需要按置信度分流复核的流程 | ⛔ **不能替代（结构性）** | 没有置信度 |
| 港股 KYC 类文件 | ⚠️ 证据不足 | 没有金额断言 |
| 扫描件、倾斜件 | ⚠️ 没和 Azure 对照 | Infinity：页面倾斜 2° 就无限复读，输出作废 |
| 贸易金融单证 | — 未覆盖 | 没有合规的公开样本 |

## PDF 处理效果：配对数据对比

| 指标 | n | Infinity | Azure DI | 读法 |
|---|---|---|---|---|
| 金额：数值原样、次数正确 | 486 | 97.5% | **100%** | Azure 显著更好（p = 0.0005）。Infinity 12 条失败里 8 条是真实遗漏 |
| 正文完整性（统一标点后） | 448 | 93.1% | **97.1%** | Azure 显著更好（2 : 20，p = 0.0001） |
| 单位与币种（统一标点后） | 93 | 98.9% | 100% | 未观察到显著差异 |
| 金额与科目同行（人工确认） | 76 | 100% | 98.7% | 未观察到显著差异 |
| 全量金额扫描（54 页 A 股金额页） | 1,544 个 | 缺 11 个，2 页 | 缺 6 个，2 页 | 未观察到显著差异；Infinity 已查实是丢表，Azure 的原因待查 |

**更正**：第一轮显示「正文完整性 Infinity 91.3%，Azure 72.5%」。第二轮查明，这是因为 Azure 会把全角标点转成半角，而判定器当时没有统一标点。统一后方向反转，旧数字作废。

| 服务与成本（口径不同，只作参考） | Infinity（测试端点） | Azure DI（公司网关） |
|---|---|---|
| 成功率 | 210/210 | 191/210 |
| 单页延迟中位数 | 22.5 s（并发 2） | 17 s（并发 4，含轮询） |
| 吞吐 | 1.6–5.6 页/分，加并发没用 | — |
| 价格 | 厂商未报价 | 牌价 $10 / 千页 |

每页约 9.6k token。若按 token 计费，输入单价要低于 **≈ $1.13 / 百万 token** 才能和 Azure 牌价持平。

## 模型基本对比

| | Infinity-Parser2 | Azure DI（prebuilt-layout） |
|---|---|---|
| 技术路线 | 视觉语言模型（VLM），整页图像直接生成 markdown | OCR + 版面分析流水线 |
| 支持格式 | 只有 PDF 和图片 | PDF、图片、Office、HTML |
| 置信度 | **无** | 每个文本片段都有 |
| 确定性 | 同一页调 3 次，99.0% 逐字相同，金额零变化 | 确定性 |
| 认不出时 | 可能漏掉或生成错误内容，调用照常正常结束 | 给出低置信度或留空 |
| 标点 | 保留全角 | 转成半角，下游需要统一处理 |
| 版本 | 只能看到别名 `inf-mllm`，看不到型号和版本 | 有 API 版本号 |
| 模型来源 | 开源权重（Apache-2.0）；自称基于 Qwen3.5，尚未证实 | 闭源托管服务 |

## POC 范围与退出标准

**先决条件**：要有替代的动因，即厂商报价显示成本优势、确实需要私有化部署，或其他明确的业务理由。解析质量本身不构成动因。

**范围**
- 港股年报、中报、招股书，加 A 股公告；只用电子版 PDF，每类至少 300 页。
- 另挑至少 50 页「页首续表」做定向测试，两边都跑。
- 强制护栏：金额与 PDF 文本层逐个对账；`finish_reason=length` 一律转人工；标点和减号统一归一化。
- 开测前厂商必须答复：型号与版本能否锁定、怎么计费、有没有置信度、生产 SLA。

**退出标准（任一触发即停）**
- 丢失或替换金额的页，显著多于 Azure。
- 不能锁定版本，也不承诺变更前通知。
- 按合同价、计入人工复核后，单页成本高于 Azure。
- 生产吞吐满足不了业务峰值，或复读退化率超过阈值。
