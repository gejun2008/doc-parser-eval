## 2. 正文 · VLM 特有指标（OCR 流水线不存在这些失败方式）

这是与 Azure DI 的**结构性差异**，不是分数高低（`architecture-findings.md`）。
OCR 流水线「认不出」→ 低置信/空；VLM「认不出」→ 可能生成一个格式正确的错数字，且 `finish_reason: stop`。

| 指标 | 定义 | OCR 对应物 | 状态 |
|---|---|---|---|
| 置信度可用性 | API 是否给逐字段置信度 | Azure 逐 span confidence | ✅ **无**（logprobs 静默忽略） |
| 置信度校准曲线 | confidence 分箱 vs 实际准确率 | Azure 可画 | 🚫 Infinity 侧无法画；只能单边报 Azure |
| 静默失败率 | 错误但无任何信号的比例 | — | ⚠️ 无置信度 → 所有错误都是静默的，写机制 |
| 重复一致性 | temp=0 同页 3 次逐字一致率 / 断言翻转率 | 确定性，≈100% | ✅ 99.0% / 0.17%（`amount` 562 条零翻转，两点同写） |
| 生成退化率 | 复读至 `max_tokens`（`finish_reason=length`） | 不存在 | ✅ 2 次观测（密集数字表、旋转 2°），确定性复现 |
| 截断率 | `finish_reason != stop` 页占比 | 不存在 | ✅ olmOCR 120 页中 1 页 |
| 数字替换型幻觉 | 金额被换成另一个格式正确的数 | 极少 | ⛔ 并入 critical error 人工核对 |
| bbox 来源 | 几何检测 vs 生成 token（0–1000 归一化） | 检测器 | ✅ 定性，附 SDK 源码 |
| 版本可观测性 | 端点能否查到档位/版本 | Azure 有 API 版本 | ✅ 只回显别名 `inf-mllm` |

**报告句式**（architecture-findings 已定）：Infinity-Parser2 用置信度、确定性、几何 bbox
三样东西换了表格结构上的优势，这笔交易在 HSBC 场景是否划算。

## 5. 服务档 · 延迟与吞吐

**所有数字只代表「测试端点 + 测量时段 + 并发条件」，不代表生产服务能力。**
测试端点表现为单副本串行排队（并发 1→8 吞吐不变），生产环境是否如此无法从外部区分（B3）。

| 指标 | 口径 | 实测 |
|---|---|---|
| 单页延迟 P50 / P95 | 并发 2，金融集 210 页，2026-09-21 | 22.5s / 54.2s |
| 同上 | 并发 2，olmOCR 120 页，2026-09-18 | 42.6s / 172.6s |
| 吞吐 | 页/分，并发 1–8 | 1.6–1.8（梯度测试）；不同时段 1.92–5.64，波动 2–3 倍 |
| 限流行为 | 超并发上限 | 静默排队，无 429、无 `retry-after` |
| 硬失败率 | 非 200 / 超时 | 金融集 0/210 |

**不做的**：与 Azure DI 比延迟（Azure 异步 API，耗时含轮询，不同口径）。
research-plan §4.3「按 1/5/30/100+ 页分档」在逐页调用架构下退化为「页数 × 单页延迟 ÷ 有效并发」，
有效并发=1 时 100 页文档约 40–60 分钟——**这个换算本身就是结论**，写进工程现实。

## 6. 服务档 · Token 与成本

### 6.1 已经能测的（不依赖厂商）

| 指标 | 金融集 210 页实测 |
|---|---|
| prompt tokens / 页 | 中位 **8,868**（300 DPI + smart_resize，由像素数决定，与内容无关） |

### 6.2 必须问厂商的（已在第一封信 A2，建议补细）

**是，需要问。** 没有计费口径就算不出成本，但只问「怎么收费」不够，要问能直接代入公式的：

1. 计费单位：按页 / 按 token / 按调用 / 包年？
2. 若按 token：**图像输入 token 与输出 token 单价分别多少**？
3. **`finish_reason=length` 的退化调用是否计费**？（单次约 32k completion 的无效输出）
4. 输入分辨率由客户端决定（DPI 越低 token 越少）——是否有推荐/强制分辨率？
   按 token 计费意味着「降分辨率省钱」与准确率直接交换，需要厂商给出推荐档
5. 阶梯价 / 承诺用量折扣
6. 私有化部署的授权与报价（权重 Apache-2.0，买的是什么）

### 6.3 不等厂商也能写的：参数化成本表

报告不给「Infinity 比 Azure 便宜/贵 X%」，给**盈亏平衡价**：

| 方案 | 单页成本公式 | 参数来源 |
|---|---|---|
| Azure DI Layout | 牌价 $10 / 1000 页 | 微软官网；**应以 HSBC 实际合同价为准**，找采购要 |
| Infinity API · 按页 | 厂商报价 | ⛔ A2 |
| Infinity API · 按 token | 8.9k × P_in + 1.0k × P_out | 实测 token × 厂商报价 |
| Infinity 自部署（二期） | GPU 小时价 ÷ 每小时页数 | **本轮不测**；厂商自报 Flash 1,624 tok/s 只能标为厂商声明 |

据此可反推：若按 token 计费，**只算输入时 P_in 需低于约 $1.13 / 百万 token 才与 Azure 牌价持平**
（$0.01 ÷ 8,868），计入输出 token 后门槛更低。这句话不依赖厂商回复就能写。

**还要加一个银行口径**：成本应按「**每页无 critical error 的有效产出**」折算，
并加上人工复核成本——没有置信度意味着无法选择性复核，只能全量复核或抽检，
这直接决定厂商 ROI 模型里 99.7% 自动化率能否成立。critical error rate 出来前这一栏空着。

## 小结：报告里的数字分四种

1. **已测、可下结论**：token/页、延迟（附条件）、一致性、限流行为、无置信度、截断/退化机制
2. **已测、样本不足只能描述**：按族准确率、泄漏对照、扰动衰减
3. **缺数据、不可砍**：critical error rate、Azure 配对对比
4. **依赖厂商**：计费单价（A2）、模型版本（A1）、生产吞吐（B3）——
   给不出就如实写「厂商未提供」，成本节用盈亏平衡价代替
