# 导出成文数据的 prompt（给公司电脑上的 AI 助手）

Azure 基线跑完后，用这段 prompt 让 Copilot 等助手导出写报告所需的全部数据。

**关键设计：不让助手总结数字，只让它运行脚本、原样输出。**
让 AI 用自然语言转述数字，是最容易出错的环节——四舍五入、合并分层、
把「未观察到显著差异」改写成「持平」。本项目的可信度建立在「每个数字都能追溯到文件」上，
中间不能过一道 AI 的手。`tools/export_for_report.py` 只读文件、只做确定性计算。

前提：公司电脑已同步到包含 `tools/export_for_report.py` 的版本（见 `docs/working/sync-prompt.md`）。

---

## 复制以下内容

```
我需要把评测数据导出给写报告的人。请严格按步骤做，不要自行总结、转述或
四舍五入任何数字。环境是 Windows PowerShell，Python 用 .venv\Scripts\python，
在仓库根目录执行。

## 第一步：确认两边都用最新断言判过

不调 API，每条几秒钟：
  .venv\Scripts\python tools\check.py runs\inf-mllm_doc2md_20260921T013924Z
再对 runs\ 下所有「azure_di_layout_ 开头、且含 results.csv」的目录各跑一次：
  .venv\Scripts\python tools\check.py runs\<该目录名>

## 第二步：运行导出脚本

  .venv\Scripts\python tools\export_for_report.py

会生成 report_input.md，并打印文件大小与「脱敏 N 处」。

## 第三步：三个客观检查点，任一不满足就停下告诉我，不要继续

1. report_input.md 第 0 节有这一行：
     过期检查：两边 results.csv 均与当前断言一致 ✓
   若出现「基于旧版断言」的警告，按提示重跑对应目录的 check.py，再从第二步开始。
2. 第 0 节「发现的 run」里，Azure 自建集和 Azure 基准都不是「✗ 缺」。
3. 如果我没做过人工审核（第 0 节显示「draft 仍有 76 条」），
   断言目录指纹应为 3319b5b063d9。不一致说明断言没有更新到最新版。
   如果做过人工审核，指纹会不同，这是正常的，跳过这一条。

## 第四步：安全检查，发出去之前必须做

在 report_input.md 里搜索以下内容：
  cognitiveservices    azure.com    Ocp-Apim    Bearer    我们 Azure 资源的名字
任何一个能搜到真实值（而不是「<已脱敏>」「<端点已脱敏>」），
停下告诉我具体在哪一行，不要输出文件内容。

## 第五步：把 report_input.md 全文原样输出

- 不删减、不改写、不总结、不重新排版表格，原样复制
- 太长就分段输出，每段开头标明「第 X/Y 段」，段与段之间不要漏行
- 输出完告诉我总共几段、文件多少 KB，方便我核对有没有粘漏
```

---

## 为什么这样写

- **第一步先重判**：断言在 2026-09-23 修过一次（金额折行截断）。若 Azure 那边的
  `results.csv` 是修之前判的，配对结果无效且看不出来
- **第三步的检查点都是客观的**：脚本会自己比对 `results.csv` 的目标值与当前断言，
  过期就打警告；断言指纹是确定值。不依赖助手自己说「已完成」
- **第四步安全检查**：脚本不导出响应头（Azure 的 `Operation-Location` 含资源端点），
  输出前已按规则脱敏。但脱敏规则不可能覆盖所有资源命名，人工再搜一遍是最后一道防线
- **第五步强调原样**：分段输出时助手容易「顺手整理」表格，数字就在这一步走样
