## B 类 · 影响结论的可靠性，强烈希望答

| # | 问题 | 为什么重要 | 我方证据 |
|---|---|---|---|
| B1 | API 层是否有办法拿到**置信度**？`logprobs` 被静默忽略，响应里也没有 `confidence` 字段 | 银行场景必须能判断「哪些字段需要人工复核」。没有置信度，「99.7% 自动化率」这类说法无法验证 | 请求带 `logprobs: true, top_logprobs: 5` 返回 **200 不报错**，但 `choices[0].logprobs` 为 `null`。`probe_out/04_page_logprobs_raw.json` |
| B2 | `temperature: 0` 下输出为何仍不确定？`seed` 参数是否真的生效？**产品层面是否提供确定性模式？** | 直接关系到输出能否作为审计证据 | 210 页 × 3 次：逐字一致 208/210 = 99.0%，断言结论翻转 2/1155 = 0.17%。不稳定集中在表格结构与全角/半角符号 |
| B3 | 测试端点是否只挂了**单副本**？「并发上限 16」指的是接受的连接数还是实际并行处理能力？**生产环境的吞吐与 SLA 是多少？** | 实测并发无效，且吞吐随时段波动 2–3 倍，无法做容量规划 | 并发 1→8 吞吐恒定 1.6–1.8 页/分；并发 20 时 19 个请求卡到 300s 超时，**无 429、无 `retry-after`**。不同日期实测 1.92 / 3.66 / 4.51 / 5.41 / 5.64 页/分。`probe_out/08_concurrency.json`、`08b_concurrency_ladder.json` |
| B4 | 在**密集数字表格**与**轻微旋转**的输入上，是否已知存在生成退化？ | 我方两次观测到确定性失败：输出同一内容无限重复直至耗尽 token 预算，三次重试均相同 | 一次为纯数字信号电平表，一次为财报页旋转 2°。均 `finish_reason=length`、`completion_tokens=32768`。单次浪费约 98k completion token 并返回无效结果 |
| B5 | **Infinity-Parser2-Fin 的权重是否开源**？ | 贵方公开材料中「权重 Apache-2.0 公开」是重要的合作前提；但 HF 上只有 Pro/Flash | 擂台页显示 93.56% 归属于 Fin |
| B6 | **PDFParser 与 Infinity-Parser2 是否同一模型**？「最低延迟」的代价是什么？ | 决定对照基线里放哪个产品 | — |

## 发信建议

- A 类四条单独成信，说明它们阻塞报告成文，给出期望回复时间
