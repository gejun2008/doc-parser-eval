# 测试集与测试结果

本文件只放**测了什么、测出什么**。怎么解读、能下什么结论，见 [`evaluation-report.md`](evaluation-report.md)。

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-24（含第二轮数据） |
| 被测 | INF TECH Infinity-Parser2 API，测试端点，服务端回显模型别名 `inf-mllm` |
| 基线 | Azure Document Intelligence `prebuilt-layout`，经公司内部网关，`outputContentFormat=markdown` |
| 调用方式 | 两边都调用 API 解析同一批页，各自输出 markdown，我方不做格式转换。Infinity 走裸 HTTP，不经厂商 SDK |
| 判定方式 | 输出与同一套断言（GT）逐条比对，只比两边都成功的页，McNemar 配对检验；不合成总分 |

## 1. 测试集

### 1.1 自建金融场景集（对照用）

各类断言查什么：

| 类型 | 查什么 |
|---|---|
| 正文完整性 `page_integrity` | 每页抽 3 段正文，查是否原样出现在输出里（查漏页、幻觉） |

| 单位币种 `unit_currency` | 表头「单位：元」「人民币千元」等是否保留 |
| 金额科目归属 `amount_label` | 金额与它的科目标签是否挨在一起（字符距离 ≤ 120） |

### 1.2 GT（断言）从哪来

每份文档一个 YAML，放在 `data/assertions/`，共 53 份。定义见 [`working/assertions.md`](working/assertions.md)，生成与审核流程见 [`working/assertions-method.md`](working/assertions-method.md)。

| GT 来源 | 条数 | 人工参与 |
|---|---|---|
| 从 PDF 文本层自动提取：正文完整性 | 480 | 无，字符取自原文 |
| 从 PDF 文本层自动提取：金额、单位币种 | 673 | 抽样审计 53 条金额，改值 1 条，GT 错误率估计 1.9% [0.3, 9.9] |
| 脚本给候选、人工逐条确认：金额科目归属 | 76 | 全部人工。确认 76 条，驳回 0 条，改值 1 条 |

人工审核在公司电脑上完成，结果回写在公司电脑的断言文件中；本机仓库里这 76 条仍是 `draft`。

## 2. 测试结果

### 2.1 按断言类型（配对集）

统计口径：严格 = 只去掉空白；宽松 = 再做全角转半角、删掉所有标点。金额类只用严格口径。
两家的标点习惯不同（Azure 会把全角标点转成半角），所以正文完整性和单位币种以宽松口径为准。

| 类型 | 口径 | n | Infinity [95% CI] | Azure [95% CI] | 只 Inf 对 : 只 Az 对 | p |
|---|---|---|---|---|---|---|
| 金额 | 严格 | 486 | 97.5% [95.7, 98.6] | 100.0% [99.2, 100.0] | 0 : 12 | 0.0005 |
| 正文完整性 | 宽松 | 448 | 93.1% [90.3, 95.1] | 97.1% [95.1, 98.3] | 2 : 20 | 0.0001 |
| 单位币种 | 宽松 | 93 | 98.9% [94.2, 99.8] | 100.0% [96.0, 100.0] | 0 : 1 | 1.0 |
| 金额科目归属 | 严格 | 76 | 100.0% [95.2, 100.0] | 98.7% [92.9, 99.8] | 1 : 0 | 1.0 |

严格口径（不采用，保留作对照）：

| 类型 | n | Infinity 通过 | Azure 通过 | 只 Inf 对 : 只 Az 对 |
|---|---|---|---|---|
| 正文完整性 | 448 | 409（91.3%） | 325（72.5%） | 99 : 15 |
| 单位币种 | 93 | 89（95.7%） | 2（2.2%） | 87 : 0 |

### 2.2 金额与科目归属失败逐条

配对集中至少一边失败的共 13 条，逐条打开原始输出、对照 PDF 文本层裁定。

| 断言 | 系统 | 判定 | 裁定 |
|---|---|---|---|
| A 股年报 002310 p225 am01–am04（4 条） | Infinity | 次数少于文本层 | **业务错误**：页首续表整段没有输出，`finish_reason=stop` |
| A 股中报 688098 p170 am01–am04（4 条） | Infinity | 找不到 | **业务错误**：页首续表的「合计」行没有输出，`finish_reason=stop` |
| A 股年报 300208 p11 am04（1 条） | Infinity | 找不到 | 非业务错误：负号用了 U+2212「−」，数值正确 |
| A 股中报 839680 p9 am01 / am03 / am04（3 条） | Infinity | 找不到 | 非业务错误：同上 |
| A 股公告 605011 p1 lp02（1 条） | Azure | 标签找不到 | 非业务错误：`元（含税）` 被转成 `元(含税)` |

合计：Infinity 8 条业务错误（集中在 2 页）、4 条格式差异；Azure 0 条业务错误、1 条格式差异。
完整断言 ID 与两边判定原文见 [`working/report-numbers-20260923.md` 表 5](working/report-numbers-20260923.md#表-5-关键字段失败明细)。

### 2.3 全量金额扫描

抽样断言每页只抽 4 个金额，所以另把页上每个 A 股写法的金额（千分位加两位小数）都查一遍（`tools/amount_scan.py`）。

**配对集**：54 页，金额出现 1,544 次。

| 系统 | 缺失次数 | 缺失率 [95% CI] | 有缺失的页 |
|---|---|---|---|
| Infinity | 11 | 0.7% [0.4, 1.3] | 2 页 |
| Azure | 6 | 0.4% [0.2, 0.8] | 2 页 |

| 页 | 文本层金额数 | Infinity 缺失 | Azure 缺失 |
|---|---|---|---|
| A 股年报 002310 p225 | 32 | 7 | 0 |
| A 股中报 688098 p170 | 46 | 4 | 4 |
| A 股中报 688098 p202 | 16 | 0 | 2 |

按页比：只 Infinity 缺 1 页、只 Azure 缺 1 页、两边都缺 1 页，未观察到显著差异。Azure 缺失的原因待查。

**配对集以外（仅 Infinity）**：210 页中 73 页含金额，出现 2,149 次，缺失 27 次，涉及 3 页。
第 3 页是 A 股年报 300572 p9，整张「分季度主要财务指标」表（16 个金额）没有输出；Azure 在该页网关超时，无法对比。
三次重复调用，缺失完全相同。

### 2.5 服务与成本

两列的测量日期、并发和调用路径都不同，**只作参考，不比优劣**。

| | Infinity（测试端点，直连） | Azure（经公司网关） |

| 并发 | 2 | 4 |
| 成功页 | 210 / 210 | 191 / 210 |
| 单页延迟 P50 / P95 | 22.5 s / 55.6 s | 17 s / 21 s（含网关与轮询） |
| 整批耗时 | 46.5 min | 187 min（含中断） |

| 吞吐时段波动 | 不同日期 1.92 / 3.66 / 4.51 / 5.41 / 5.64 页/分 | 未测 |
| 价格 | 未报价 | 牌价 $10 / 千页 |
